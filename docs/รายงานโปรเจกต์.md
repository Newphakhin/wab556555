## บทที่ 1 บทนำและข้อกำหนดความต้องการของระบบ (SRS)

### 1.1 ภาพรวมของระบบ
**Simple Booking System for Lab Room** เป็นเว็บแอปพลิเคชันสำหรับจัดการการจองห้องปฏิบัติการของสาขาวิชาวิศวกรรมคอมพิวเตอร์ มหาวิทยาลัยกาฬสินธุ์ เพื่อให้ผู้ใช้งาน (นักศึกษา อาจารย์ และเจ้าหน้าที่) สามารถตรวจสอบห้องว่าง ส่งคำขอจองห้อง และติดตามสถานะการจองได้อย่างสะดวก ลดปัญหาการจองซ้ำซ้อน การจดบันทึกด้วยเอกสารหรือแชทที่ไม่เป็นระบบ และช่วยให้ผู้ดูแลระบบอนุมัติหรือปฏิเสธคำขอจองได้ง่ายขึ้น

### 1.2 วัตถุประสงค์ของระบบ
1. เพื่อพัฒนาเว็บแอปพลิเคชันสำหรับจองห้องปฏิบัติการของสาขาวิชาวิศวกรรมคอมพิวเตอร์
2. เพื่อให้ผู้ใช้สามารถตรวจสอบรายการจองและสถานะห้องได้อย่างสะดวก
3. เพื่อป้องกันการจองห้องซ้ำซ้อนในวันและเวลาเดียวกัน
4. เพื่อให้ผู้ดูแลระบบสามารถอนุมัติ ยกเลิก หรือปฏิเสธคำขอจองได้
5. เพื่อฝึกพัฒนาเว็บแอปพลิเคชันที่มี CRUD, validation, role-based view, calendar/table view และ dashboard
6. เพื่อประยุกต์ใช้ AI tools ช่วยวางโครงสร้างระบบ เขียนโค้ด แก้บั๊ก และจัดทำเอกสารประกอบโปรเจกต์

### 1.3 บทบาทผู้ใช้งาน
- **User (นักศึกษา / อาจารย์ / เจ้าหน้าที่):** ดูรายการห้อง, ดูรายละเอียดห้อง, ตรวจสอบตารางการจอง, ส่งคำขอจองห้อง, ดูสถานะคำขอจองของตนเอง และยกเลิกคำขอจองของตนเองก่อนถึงเวลาเริ่ม
- **Admin (ผู้ดูแลระบบ):** เข้าสู่ระบบผ่านหน้า `#/login` (รหัสผ่าน `admin123`), เพิ่ม/แก้ไข/ลบห้องปฏิบัติการ, ดูรายการคำขอจองทั้งหมด, อนุมัติ/ปฏิเสธ (พร้อมระบุเหตุผล)/ยกเลิกรายการจอง, ค้นหาและกรองรายการจอง และดู Dashboard สรุปข้อมูลการใช้ห้อง

## บทที่ 2 การวิเคราะห์และออกแบบระบบ

### 2.1 สถาปัตยกรรมระบบ (3-Layer Architecture)
- **Presentation Layer (`js/pages/`, `js/components/`):** จัดการการแสดงผล UI ทั้ง 10 หน้าจอ และรับอินพุตจากผู้ใช้
- **Service Layer (`js/services/roomService.js`, `js/services/bookingService.js`):** ประสานงานระหว่าง UI, กฎธุรกิจ และฐานข้อมูลแบบ `async/await`
- **Domain & Data Layer (`js/domain/rules.js`, `js/db.js`, `js/session.js`):** เก็บกฎธุรกิจแบบ Pure Functions และบันทึกข้อมูลลงฐานข้อมูล `IndexedDB` (`LabBookingDB`)

### 2.2 เงื่อนไขการตรวจสอบเวลาซ้ำซ้อน (SRS ข้อ 14)
ระบบแปลงเวลา `HH:MM` เป็นจำนวนนาทีนับจากเที่ยงคืน (`toMin(t) = h * 60 + m`) และตรวจสอบการทับซ้อนกับรายการที่มีสถานะ `Approved` ในห้องและวันเดียวกันด้วยเงื่อนไข:

```javascript
new_start_time < existing_end_time && new_end_time > existing_start_time
```

| รายการเดิม (`Approved`) | รายการใหม่ | ผลลัพธ์ |
|---|---|---|
| `09:00–11:00` | `10:00–12:00` | ซ้ำซ้อน |
| `09:00–11:00` | `08:00–09:30` | ซ้ำซ้อน |
| `09:00–11:00` | `11:00–12:00` | ไม่ซ้ำซ้อน (เวลาต่อกันพอดี) |
| `13:00–15:00` | `09:00–12:00` | ไม่ซ้ำซ้อน |

## บทที่ 3 การพัฒนาระบบและข้อมูลตัวอย่าง

### 3.1 ข้อมูลห้องปฏิบัติการตัวอย่าง 5 ห้อง (`js/seed.js`)
1. **CE-LAB-01:** Computer Engineering Lab 1 (ความจุ 30 คน) — `Computer, Projector, Internet`
2. **CE-LAB-02:** Computer Engineering Lab 2 (ความจุ 25 คน) — `Computer, Smart TV, Internet`
3. **NET-LAB:** Network Laboratory (ความจุ 20 คน) — `Router, Switch, Network Cable, Rack`
4. **IOT-LAB:** IoT and Embedded Systems Lab (ความจุ 20 คน) — `Arduino, ESP32, Sensor Kit, Oscilloscope`
5. **PROJECT-ROOM:** Student Project Room (ความจุ 10 คน) — `Whiteboard, Meeting Table, Power Outlet`

### 3.2 ข้อมูลการจองตัวอย่าง 16 รายการ
ประกอบด้วยรายการจอง `bk-01` ถึง `bk-16` ครอบคลุมทั้งสถานะ `Pending`, `Approved`, `Rejected` และ `Cancelled`

## บทที่ 5 สรุปการใช้ AI Tools และการนำขึ้นระบบจริง

### 5.1 สรุปการใช้ AI Tools (Antigravity)
1. ช่วยออกแบบโครงสร้างโปรเจกต์แบบแยกชั้น (`pages`, `services`, `domain`, `components`, `utils`)
2. ช่วยออกแบบ Schema ของฐานข้อมูล `IndexedDB` (`rooms`, `bookings`)
3. ช่วยเขียน ES Modules สำหรับหน้าจอทั้ง 10 หน้า และ Reusable Components
4. ช่วยเขียนระบบตรวจสอบข้อมูล `validateBooking` และ `validateRoom`
5. ช่วยพัฒนาฟังก์ชันตรวจสอบเวลาซ้ำซ้อน `isOverlap` และ `findConflicts`
6. ช่วยสร้าง Dashboard แสดงกราฟด้วย Chart.js
7. ช่วยเขียนและปรับปรุงชุดทดสอบอัตโนมัติ 48 ข้อ
8. ช่วยสร้างข้อมูลตัวอย่างห้อง 5 ห้อง และรายการจอง 16 รายการ
9. ช่วยปรับแต่ง CSS ให้รองรับหน้าจอมือถือ (Responsive Design)
10. ช่วยจัดทำเอกสาร `README.md` และเล่มรายงานโปรเจกต์ฉบับสมบูรณ์
